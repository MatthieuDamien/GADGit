Nous devons **garantir** que votre service MongoDB par défaut est arrêté pour que votre instance locale puisse s'initialiser.

### Étape 1 : Arrêter le Service Windows

1. **Fermez le terminal** où vous avez lancé le `mongod --replSet rs0`.
    
2. Dans la barre de recherche Windows, tapez **"Services"** et ouvrez l'application.
    
3. Recherchez le service nommé **"MongoDB Server"** (ou "MongoDB" suivi de votre version).
    
4. Faites un clic droit dessus et sélectionnez **"Arrêter"**.
    
5. Pour éviter que cela ne se reproduise, vous pouvez aussi faire un double-clic sur le service et changer le "Type de démarrage" à **"Manuel"**.
### Étape 2 : Redémarrer Votre Instance Replica Set

1. **Ouvrez un nouveau terminal.**
    
2. Relancez votre serveur en mode Replica Set :
    
    ```bash
    mongod --port 27017 --dbpath C:\Users\skycr\ProDisk\Stages\GAD\CloneGAD\gadpipeline\data\db\rs0 --replSet rs0
    ```
    
    Cette fois, le log devrait être plus propre car aucune autre instance n'occupe le port.
### Étape 3 : Initialisation Finale

1. **Ouvrez un deuxième nouveau terminal.**
    
2. Lancez le shell :
    
    ```bash
    mongosh
    ```
    
1. Exécutez l'initialisation :
    ```JavaScript
    rs.initiate()
    ```
    

Si le service par défaut a été correctement arrêté, l'initialisation devrait fonctionner, et vous verrez :

- Le prompt du shell changera en **`rs0:PRIMARY>`**.
    
- Le premier terminal (les logs `mongod`) affichera des messages confirmant l'élection d'un primaire, et les erreurs de l'oplog disparaîtront.
    

Une fois que vous avez **`rs0:PRIMARY>`**, vous avez terminé la configuration de la base de données et vous pouvez passer au code Node.js.

Pour avoir les infos :
```JavaScript
rs.status()
```
